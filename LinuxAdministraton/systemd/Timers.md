## 2. Таймеры (Timer Units)
Таймеры systemd полностью заменяют `cron`. Они обеспечивают точный запуск (с точностью до миллисекунд), привязку к событиям системы, сбор логов в `journalctl` и управление через единый интерфейс `systemctl`.
Это современный механизм планирования и автоматизации задач в Linux, полностью заменяющий классический `cron`. В отличие от `cron`, таймеры интегрированы в общую экосистему systemd: они запускают задачи в изоляции (cgroups), ведут подробный журнал (`journalctl`), отслеживают статус выполнения и поддерживают гибкие зависимости.
Таймер всегда работает в паре с сервисом:
1. `myapp-backup.service` — описание запускаемой задачи (без секции `[Install]`).
2. `myapp-backup.timer` — расписание запуска сервиса с таким же именем.
### Пример `.service` для таймера (`/etc/systemd/system/myapp-backup.service`):

```toml
[Unit]
Description=Database Daily Backup Task

[Service]
Type=oneshot
User=postgres
ExecStart=/usr/local/bin/backup-script.sh
```
### Пример `.timer` файла (`/etc/systemd/system/myapp-backup.timer`):

```TOML
[Unit]
Description=Run Database Backup Daily and on Boot

[Timer]
# Запуск через 15 минут после загрузки системы:
OnBootSec=15min

# Календарное расписание (Каждый день в 03:30:00):
OnCalendar=*-*-* 03:30:00

# Разброс времени запуска (предотвращает одновременно высокие нагрузки при куче таймеров):
RandomizedDelaySec=5min

# Если система была выключена во время срабатывания — запустить сразу при включении:
Persistent=true

[Install]
WantedBy=timers.target
```
### Анатомия секции `[Timer]` и доступные атрибуты
Секция `[Timer]` определяет правила срабатывания задачи. Таймеры делятся на два типа: **монотонные** (relative/относительные) и **календарные** (real-time/абсолютные).

| **Директива**             | **Тип / Формат**                     | **Описание и применение**                                                                                                                                              |
| ------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`OnCalendar=`**         | Календарное выражение                | **Абсолютное время.** Запуск в конкретные даты и дни недели (аналог `cron`).                                                                                           |
| **`OnBootSec=`**          | Относительное время (`15min`, `1h`)  | Запуск через указанный интервал **после загрузки системы**.                                                                                                            |
| **`OnStartupSec=`**       | Относительное время (`30s`)          | Запуск через указанный интервал **после старта самого процесса systemd**.                                                                                              |
| **`OnActiveSec=`**        | Относительное время (`5m`)           | Запуск через указанный интервал **после активации самого таймера**.                                                                                                    |
| **`OnUnitActiveSec=`**    | Относительное время (`1d`, `12h`)    | Запуск через интервал **после последнего запуска связанного сервиса**. Позволяет организовать периодический цикл.                                                      |
| **`OnUnitInactiveSec=`**  | Относительное время (`10m`)          | Запуск через интервал **после последнего завершения связанного сервиса**.                                                                                              |
| **`Persistent=`**         | `true` / `false` _(по умолч: false)_ | **Catch-up запуск.** Если система была выключена в момент срабатывания `OnCalendar`, при следующем включении systemd **сразу же запустит пропущенную задачу**.         |
| **`RandomizedDelaySec=`** | Время (`10m`, `1h`)                  | **Случайный разброс (Jitter).** Задержка запуска на случайный отрезок времени от `0` до указанного значения. Предотвращает пиковые нагрузки при массовом старте задач. |
| **`AccuracySec=`**        | Время (`1us`, `1m`) _(по умолч: 1m)_ | **Точность срабатывания.** Позволяет ядру объединять (coalesce) просыпания CPU для нескольких задач с целью экономии энергии.                                          |
| **`Unit=`**               | Имя юнита (`custom.service`)         | Указывается, только если имя `.service` юнита **отличается** от имени `.timer` файла.                                                                                  |
| **`RemainAfterElapse=`**  | `true` / `false`                     | Позволяет удержать таймер в состоянии `active`, даже если время его работы прошло и он больше не сработает.                                                            |



### Детальный разбор `OnCalendar` (Системный Календарь)
#### Примеры расписания (`OnCalendar`):
- `Mon,Fri *-*-* 02:00:00` — каждый понедельник и пятницу в 02:00.
- `*-*-01 00:00:00` — первого числа каждого месяца в полночь.
- `hourly` или `daily` — встроенные макросы.

Формат `OnCalendar` использует структуру:
`ДеньНедели Год-Месяц-День Часы:Минуты:Секунды`
#### Синтаксические правила и подстановочные знаки:
- `*` — любое значение.
- `..` — диапазон значений (`1..5` — с 1 по 5).
- `,` — перечисление значений (`Mon,Fri` — понедельник и пятница).
- `~` — отсчет с конца месяца (`*-*-~01` — последний день месяца, `*-*-~02` — предпоследний день).
### Готовые шаблоны и примеры выражения:

| **Выражение OnCalendar**        | **Расшифровка расписания**                                 |
| ------------------------------- | ---------------------------------------------------------- |
| `*-*-* 00:00:00`                | Каждый день в полночь.                                     |
| `Mon..Fri *-*-* 09:00:00`       | Каждое утро по будням (с понедельника по пятницу) в 09:00. |
| `*-*-01 03:30:00`               | Каждое 1-е число месяца в 03:30 утра.                      |
| `Mon,Wed,Fri *-*-* 02,04:00:00` | По понедельникам, средам и пятницам в 02:00 и 04:00.       |
| `*-*-~01 23:00:00`              | В последний день каждого месяца в 23:00.                   |
| `hourly`                        | В начале каждого часа (`*-*-* *:00:00`).                   |
| `daily` / `midnight`            | Каждый день в полночь (`*-*-* 00:00:00`).                  |
| `weekly`                        | Каждое воскресенье в полночь (`Sun *-*-* 00:00:00`).       |

> **Инструмент проверки** синтаксиса календаря перед деплоем:

```bash
systemd-analyze calendar "Mon,Fri *-*-* 02:00:00"
```
> Вывод покажет следующее время срабатывания и точную интерпретацию выражения.


### Команды для работы с таймерами:

```Bash
# Перезагрузить конфигурацию диска
sudo systemctl daemon-reload

# Включить и запустить таймер
sudo systemctl enable --now myapp-backup.timer

# Посмотреть все активные таймеры и время следующего срабатывания
systemctl list-timers
# Проверить подробный статус конкретного таймера и связанные события: 
systemctl status mytask.timer

# Проверить синтаксис OnCalendar
systemd-analyze calendar "Mon,Fri *-*-* 02:00:00"
# Принудительный ручной запуск задачи вне расписания
# Если вам нужно запустить сервис таймера прямо сейчас, запускается **`.service`**, а не `.timer`:
sudo systemctl start db-backup.service
```

### Создание одноразовых (Transient) таймеров на лету

Не обязательно создавать файлы `.service` и `.timer` на диске для разовых или временных задач. Утилита `systemd-run` позволяет создавать таймеры на лету:
```bash
# Запустить скрипт ровно через 2 часа:
systemd-run --on-active="2h" /usr/local/bin/cleanup.sh

# Запустить скрипт завтра в 04:00 утра с изоляцией по памяти:
systemd-run --on-calendar="2026-10-01 04:00:00" -p MemoryMax=500M /opt/scripts/export.sh
```
### Сравнение: systemd Timers vs. Cron

| **Критерий**             | **cron / crontab**                                                                          | **systemd.timer**                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Минимальный интервал** | 1 минута                                                                                    | Миллисекунды / Микросекунды                                                                                           |
| **Изоляция и ресурсы**   | Процесс заводится в общей сессии, наследует ограниченные лимиты cron-демона.                | Запуск в изолированном `.service` с индивидуальными лимитами CPU, RAM (`MemoryMax`), Cgroups/Slices.                  |
| **Логирование**          | Вывод `stdout`/`stderr` отправляется по почте (`mail`) или пишется в системный `syslog`.    | Все логи собираются автоматически в `journalctl -u service-name` с поддержкой JSON и метаданных.                      |
| **Пропущенные задачи**   | Требует отдельной утилиты `anacron`.                                                        | Встроено из коробки директивой `Persistent=true`.                                                                     |
| **Управление и статус**  | Задачи «невидимы» для системных утилит статуса. Трудно узнать результат последнего запуска. | Полная интеграция с `systemctl status`. Виден код выхода, статус `active/failed`, время последнего/следующего старта. |
| **Случайный сдвиг**      | Настраивается через `sleep $((RANDOM \% 60))` внутри bash-скрипта.                          | Встроено из коробки: `RandomizedDelaySec=15m`.                                                                        |
| **Зависимости**          | Отсутствуют. Скрипт упадет, если нет сети или БД.                                           | Полная поддержка `After=`, `Wants=`, `Requires=network-online.target`.                                                |
